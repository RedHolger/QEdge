## 3. What the current tests actually cover

Covered:

- store/retrieve/clear on a synthetic cache;
- FIFO, LRU, and KeyDiff eviction boundaries;
- QUOKA only as a cache-policy object, not query-aware attention;
- QNN stub op dispatch and CPU-output parity;
- QNN power-report fields are positive.

Not covered:

- loading a real model or tokenizer;
- reading safetensors/GGUF weights;
- a real transformer forward pass;
- real attention semantics;
- cache quality or task accuracy;
- shape validation in Release builds;
- any Snapdragon/QNN execution;
- any power, thermal, or energy measurement.

## 4. Blocking findings

1. **No real model runtime.** There is no weight loader, tokenizer, or generation loop. `scripts/download_model.py` only downloads files, and `models/` is empty. The C++ code has a `vocab_size` config field, but no code reads a real vocabulary or model tensor.

2. **The benchmark is synthetic.** `Benchmark::generate_random_tensor` constructs `std::mt19937 rng(42)` on every call (`src/benchmark/benchmark.cpp:12`). Every K/V tensor starts from the same seed and is therefore identical. It is not model input.

3. **The headline cache run cannot evict.** `kv_cache_capacity=512` and `num_layers=8` produce `max_per_layer=64` (`src/kv_cache/kv_cache.cpp:12`). The benchmark generates exactly 64 tokens (`src/main.cpp:141`). The 100% hit rate and zero evictions are structurally guaranteed, not a policy result.

4. **Attention shapes are inconsistent.** The benchmark creates `q` with batch `n_heads=32` but retrieves `k_ret`/`v_ret` with batch 1 (`src/benchmark/benchmark.cpp:57-59, 73-74`). `CPUBackend::dot_product_attention` indexes `k` and `v` using the query batch (`src/backend/cpu_backend.cpp:141-148`). In Release, `assert` is disabled, so this is an out-of-bounds read by inspection. I did not run an ASan build in this audit; this finding is from code inspection.

5. **QUOKA is not query-aware.** The policy computes an average key and evicts the key least similar to that average (`src/kv_cache/kv_cache.cpp:130-151`). There is no query vector in the cache API. It must not be described as query-oriented selection.

6. **KeyDiff is not pair-redundancy.** It compares each key to the newest key (`src/kv_cache/kv_cache.cpp:111-127`), not to the most similar key pair. The README's "evicts redundant KV pairs via cosine similarity" overstates it.

7. **Metal attention is not attention.** `MetalBackend::attention` returns `matmul(q, k)` and `fused_qk_v_attention` returns the same scores; there is no softmax and no value multiplication (`src/backend/metal_backend.mm:111-119`).

8. **QNN is a CPU stub.** `QnnStubBackend::is_available()` returns true, but every op delegates to `CPUBackend`. No QNN SDK or HTP runtime was found in common locations, and no Snapdragon device is attached. The QNN numbers are Mac CPU numbers.

9. **The power metric mixes time bases.** `tokens_per_sec` comes from the full benchmark, while `estimated_mj` comes from accumulated per-op profile time (`src/backend/qnn_stub_backend.cpp:188-212`). This makes `tok/mJ` unstable. The recommendation loop can print FIFO as best and then unconditionally print a QUOKA claim (`src/benchmark/power_report.cpp:50-55`).

10. **The portability claim is false.** CMake links macOS Accelerate, Foundation, Metal, and MetalPerformanceShaders, and includes Objective-C++ Metal code. There is no Linux/Android or QNN build path.

11. **README claims are stale or unsupported.** Examples: 12,460 tok/s, 3,346 Metal tok/s, 21/21 tests, 40% higher QUOKA tok/mJ, and "production-grade" QNN abstraction. The observed numbers and code do not support them.

12. **Packaging and license are incomplete.** README displays an MIT badge (`README.md:23,31`) and links to `LICENSE` (`README.md:407-409`), but no `LICENSE` file is present. `build/` is ignored but present. `tests/test_kv_cache.cpp` has trailing whitespace at line 195.

## 7. Risks for stage 01

The combined, ranked top-10 risk register is at `/Users/manuvashistha/Developer/qualcomm/handoff/00/risks.md`.

- The CMake build is macOS-specific; making it "portable" may require splitting the CPU backend from the Metal/QNN backends.
- The untracked QNN files must be preserved; they are part of the current work.
- A clean build currently succeeds, but the README's license link and the missing model path are broken.
- The synthetic benchmark should be moved to `legacy/` or clearly labelled; do not delete the historical numbers.
- The QNN stub should be retained as an interface prototype, not as evidence of NPU execution.
- No model should be downloaded in stage 01.
