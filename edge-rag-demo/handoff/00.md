- footwear queries return zero candidates;
- SQLite-backed attribute verification returns SUPPORTED, CONTRADICTED, and UNKNOWN in three narrow cases;

Not covered:

- real generation grounded in the verification statuses;
- refusal/abstention when all candidates are CONTRADICTED or UNKNOWN;
- missing units, ambiguous units, or query defaults;
- verdict-level filtering (the demo prints contradicted candidates);
- source/license update or tamper detection;
- a real NPU, QNN SDK, Snapdragon device, power meter, or thermal measurement;

The tests are green, but several encode the current behaviour rather than validating it. `tests/test_pipeline.py:44` asserts that the generated response contains “matches your requirements”; `tests/test_pipeline.py:123-132` asserts the hardcoded NPU percentage, not an NPU measurement; `tests/test_pipeline.py:134-144` tests Docker absence, not self-containment.

## 4. Blocking findings

1. **The project is not self-contained.** `.venv` is a symlink to `/Users/manuvashistha/Developer/Manu-Vashisth-Personal/discoveryeval/.venv`. `uv run` therefore resolves Python and packages from another repository. A clean `uv sync` in this directory would not reproduce the test environment.

2. **Absolute paths point outside the repository.**
   - `demo_pipeline.py:39` — external catalog path.
   - `tests/test_pipeline.py:28` — same external catalog path.
   - `src/edge_rag/retriever.py:11` — external `discoveryeval` root.
   - `src/edge_rag/verifier.py:10` — external `evidence-rag` root.
   - `src/edge_rag/generator.py:10` — sibling `llm-inference` root.

3. **The declared dependencies are incomplete.** `pyproject.toml` declares only `numpy`, `pillow`, and `pydantic`; `uv.lock` contains no `torch`, `faiss`, `sentence-transformers`, `open-clip-torch`, or `rank-bm25`. The actual retrieval path imports those through the external `discoveryeval` package.

4. **The generator is unconditional.** `src/edge_rag/generator.py:72` always returns `"… matches your requirements"` regardless of verification status. The adversarial run confirms this for all-CONTRADICTED and all-UNKNOWN inputs. It must be replaced by grounded wording and abstention before any “hallucination-resistant” claim.

5. **The pipeline invents requirements.** If `parse_requirements` returns nothing and the query contains “chair” or “seat”, `demo_pipeline.py:52-54` injects `{"width_lte_cm": 60.0, "material": "oak"}`. The “red chair” run therefore checks width and oak that the user never requested. This is not a harmless default; it changes the verdict.

6. **Missing units default silently to centimetres.** `src/edge_rag/verifier.py:130-139` treats a bare number as cm. The 24-inch example converts correctly, but the parser has no rejection path for ambiguous or missing units and no test for it.

7. **The NPU percentage is metadata arithmetic.** `PipelineProfiler.STAGE_INFO` hardcodes `RETRIEVE` and `VERIFY` as NPU candidates (`src/edge_rag/profiler.py:12-16`). The 100% figure in the demo is the sum of those flags, not a measurement of offloadable work. There is no QNN SDK or Snapdragon device on this machine.

8. **The Snapdragon projection is invented.** `src/edge_rag/profiler.py:46-51` applies fixed 25x and 5x speedups; `demo_pipeline.py:132-133` prints “< 3 ms.” These are assumptions, not device measurements. The README repeats the same projection at `README.md:34-41`.

9. **The benchmark footer is stale or hardcoded.** The live QNN stub measured 703–740 tok/mJ for QUOKA across three logged runs (`llm-inference/handoff/00/logs/llm_qnn_bench*.log`), while the demo footers printed 723, 726, and 861 tok/mJ, and the README claims 6,368 tok/mJ and a 79% hit rate. The fallback in `src/edge_rag/generator.py:50-55` hardcodes `79%` and `6368 tok/mJ`.

10. **The 40% memory reduction is unverified.** The QNN stub reports the same 0.95 MB peak for FIFO, LRU, KeyDiff, and QUOKA. No memory comparison supports the README claim.

11. **“Tamper-proof” and “hallucination-free” are unsupported.** The evidence store is local SQLite; there is no threat model, signature, hash-chain, or tamper test. The generator contradicts the “hallucination-free” claim directly.

12. **The reported timings vary substantially.** The three demo runs were 57.9 ms, 76.1 ms, and 113.3 ms; the README reports ~55 ms and ~28 ms. The profiler time excludes process startup and model loading. These are baseline observations, not a stable benchmark.

13. **The package metadata is incomplete.** There is no project `LICENSE` file. The README does not describe the external runtime prerequisites. The build backend declares only `src/edge_rag`, while the demo and tests live outside the package.

## 8. Risks for stage 01

The combined, ranked top-10 risk register is at `/Users/manuvashistha/Developer/qualcomm/handoff/00/risks.md`.

- The external `.venv` symlink is a reproducibility hazard and may break if `discoveryeval` moves.
- The external catalog and indexes are the actual data path; stage 01 must decide whether to vendor a small fixture or add a documented adapter.
- The current tests are fast but mostly integration tests against an external environment; they cannot run in CI as-is.
- The generator and default-requirement logic must not be “fixed” by simply changing the message; the pipeline needs explicit verdict handling and abstention semantics.
- The current 500-row catalogue is larger than a minimal fixture but far smaller than production; keep it as the Tier 1 dataset.
- Do not download models or regenerate indexes in stage 01.
- No NPU/QNN claims may enter the README until a device run exists.
