Research Headquarters in San Diego, algorithmic investigation focuses on breaking the quadratic compute bottleneck of Transformer prefill (O(T2)) and the linear memory growth of the Key-Value (KV) cache during autoregressive decoding. Standard FlashAttention optimizes tile locality in SRAM without reducing the asymptotic FLOP count or the byte volume transferred across the memory bus. To resolve this at the algorithmic layer, the San Diego team established three foundational paradigms for training-free KV management: KeyDiff, QuoKA, and CAOTE.KeyDiff (arXiv:2504.15364, NeurIPS 2025) exploits an empirical geometric invariant of Transformer representations: keys that are geometrically distinctive within the latent key space consistently receive higher attention weights from future queries. Rather than relying on historical attention scores—which suffer from positional bias and fail to generalize across shifting context windows—KeyDiff formulates cache eviction as a subset selection problem that maximizes pairwise cosine diversity. For a cached key matrix K∈Rn×d exceeding a target token budget N, KeyDiff computes an anchor vector equal to the mean of the normalized keys currently resident in the cache, evaluates the cosine similarity between each key and the anchor, and retains the N tokens with the lowest similarity to the mean anchor:$$S_{\text{KeyDiff}} = \text{topk}\left( -\text{CosSim}(K, \mu_K), N \right), \quad \text{where } \mu_K = \frac{1}{n} \sum_{i=1}^{n} \frac{k_i}{\|k_i\|_2}$$Evaluated on Llama-3.1-8B-Instruct and Llama-3.2-3B-Instruct across the LongBench benchmark suite with block size B=128, KeyDiff achieves less than a $0.04\%$ performance gap from a non-evicting full-cache baseline at an 8K token budget ($\sim 23\%$ KV compression) and only a $1.5\%$ gap at a 6K budget ($\sim 33\%$ compression), outperforming Sink Attention and TOVA.While KeyDiff governs memory footprint during long-context decoding, prefill latency frequently consumes over $70\%$ of total runtime on edge accelerators. In chunked prefill regimes—where an input prompt X is partitioned into chunks $\{X_0, X_1, \dots, X_{N_B-1}\}$ so that activation buffers fit within on-chip SRAM—the query length Q is much smaller than the accumulated key-value length KV (Q≪KV). Traditional block-sparse attention kernels suffer severe efficiency degradation in this regime because small query blocks cannot amortize sparse mask interpretation and irregular memory gathers, while online pattern search overhead scales cumulatively with each chunk. To overcome this, San Diego researchers introduced QuoKA (Query-Oriented KV Selection for Efficient LLM Prefill, arXiv:2602.08722, ICLR 2026). QuoKA operates exclusively through standard dense linear algebra primitives across three deterministic stages per chunk Xi. In the first stage, query subselection, the algorithm exploits the high geometric redundancy of queries within a chunk by computing the mean query vector MQ=1|Xi|q∈Xiq and retaining only the NQ queries with the largest angular distance (cosine dissimilarity) from MQ. In the second stage, cosine-similarity scoring, the subselected informative queries Qsub∈RNQ×d score the accumulated keys K∈RTpast×d via cosine similarity. In the third stage, score aggregation and dense execution, these scores are aggregated across queries and Grouped-Query Attention (GQA) head groups to gather a reduced cache subset of budget BSA, which is fed directly into a standard dense attention kernel. Through this mechanism, QuoKA delivers a 5× attention module speedup at 30K tokens, a 3× Time-To-First-Token (TTFT) reduction at 50K tokens, and $10\text{--}20\%$ higher accuracy than competing selective methods on LongBench while utilizing $88\%$ fewer KV pairs.Extending beyond key-only geometry, CAOTE (arXiv:2504.14051, 2026) and ValueDiff (September 2026) prove that ignoring the Value matrix V during eviction introduces unbounded reconstruction error in the attention output Oattn=AV. CAOTE minimizes the perturbation in the post-attention hidden state by weighting token eviction scores with the value vector norm and output projection sensitivity, consistently improving downstream accuracy on Llama-3 and Qwen-2.5 models when paired with attention-score or geometric selectors. Complementing these attention optimizations, San Diego's DeltaS (arXiv:2609.27470) addresses KV eviction in hybrid Gated Linear Attention architectures where weak attention sinks destabilize traditional selectors, while parallel work on Recursive Speculative Decoding (sampling without replacement) and Direct Alignment of Draft Models accelerates memory-bound token generation across text and multimodal LLMs.Amsterdam and Seoul Hubs: Ultra-Low-Bit Quantization, AIMET, and Episodic MemoryWhile San Diego optimizes the structural complexity of sequence processing, the Amsterdam and Seoul research hubs target the bit-width of weights, activations, and KV states, alongside hardware-friendly operator approximations. The Amsterdam hub pioneered the AI Model Efficiency Toolkit (AIMET), establishing the mathematical foundations that allow Qualcomm's Hexagon NPU to execute integer and mixed-precision arithmetic at scale. Data-Free Quantization (DFQ) equalizes cross-layer weight ranges and corrects bias shifts using batch-normalization statistics without calibration data, enabling seamless FP32-to-INT8 conversion. To push weight precision down to 4 bits without retraining, Amsterdam developed AdaRound (Adaptive Rounding), which replaces naive round-to-nearest operations with a layer-wise quadratic optimization over a small unlabeled calibration sample, yielding an over 8× improvement in performance per watt for 4-bit weight quantization while preserving near-FP32 accuracy. Further unifying pruning and quantization, Bayesian Bits frames mixed-precision bit-width selection as variational inference over power-of-two bit gates, while Spatial SVD and channel pruning reduce multiply-accumulate (MAC) operations by $50\%$ within $1\%$ accuracy of uncompressed baselines.Building upon AIMET's post-training foundation, the Seoul research hub and its academic partners at Seoul National University have pushed transformer compression into the sub-4-bit and multi-session agentic regimes. In the domain of ultra-low-bit weight, activation, and KV quantization, NSNQuant (NeurIPS 2025) introduces a calibration-free double-normalization scheme—normalizing across both token and channel dimensions prior to vector quantization—to compress the KV cache into low-bit representations without runtime calibration overhead. Similarly, Rotate, Clip, and Partition (W2A4KV4) combines Grouped Sequency-arranged Walsh-Hadamard rotations with learnable non-uniform quantizers to suppress activation outliers, enabling simultaneous 2-bit weights, 4-bit activations, and 4-bit KV caches. To recover accuracy in 2-bit and ternary LLMs, RA-LoRA (ACL 2024), RILQ (AAAI 2025), and Token-Scaled Logit Distillation (NeurIPS 2023) apply rank-insensitive Low-Rank Adaptation error compensation and teacher intervention during Quantization-Aware Training. Recognizing that edge assistants operate across multi-turn sessions and continuous video streams, the Seoul team also pioneered episodic and streaming KV compression through InfiniPot (EMNLP 2024) and InfiniPot-V (NeurIPS 2025) for constant-memory streaming inference, EpiCache (ICML 2026) for episodic KV memory consolidation in resource-constrained long-term conversations, BeaconKV (ICML 2026) for beacon-query guided compression in large reasoning models, and Tangram for non-uniform multi-turn KV allocation. Finally, because transcendental operations in Softmax, SiLU, and RMSNorm bottleneck vector units on mobile NPUs, Seoul's NN-LUT (DAC 2022) replaces non-linear activations with neural-approximated piecewise linear Lookup Tables mapped directly to hardware vector instructions.Silicon-Runtime Co-Design: Hexagon NPU Microarchitecture and Memory HierarchyTranslating these algorithmic breakthroughs into industry-grade products requires engineering directly against the silicon physics of the Qualcomm Hexagon NPU (Hexagon Tensor Processor, HTP)—specifically architecture versions V73 (Snapdragon 8 Gen 2 / SM8550), V75 (Snapdragon 8 Gen 3 / SM8650 and Snapdragon X Elite), V79 (Snapdragon 8 Elite / SM8750), and V81 (Snapdragon 8 Elite Gen 5 / SM8850).Compute Units, VTCM Addressing, and HMX Tile Permutation PhysicsUnlike homogeneous GPUs that rely on massive thread-level parallelism and hardware-managed caches to hide memory latency, the Hexagon NPU employs a hybrid VLIW scalar + vector (HVX) + matrix (HMX) architecture designed to maximize compute density per milliwatt. The processor incorporates 6 to 8 scalar Very Long Instruction Word (VLIW) hardware threads for control logic; every vector or matrix instruction is dispatched from one of four VLIW execution slots within a scalar core. The vector subsystem consists of 4 to 6 HVX (Hexagon Vector eXtension) units, each maintaining 32 vector registers of 1024-bit width (128 bytes per register), while the matrix subsystem comprises 1 to 2 HMX (Hexagon Matrix eXtension) units supporting INT4, INT8, INT16, and FP16 precisions.A critical hardware constraint exposed by low-level Hexagon SDK profiling is the asymmetric memory accessibility and throughput across these units. The NPU memory hierarchy contains a shared 1MiB L2 cache—populated from LPDDR5X via the l2fetch instruction at 20--30GB/s (26GB/s nominal)—and an 8MiB software-managed Tightly Coupled Memory (VTCM) populated via asynchronous 1D/2D Direct Memory Access (DMA) transfers at ∼60GB/s. While HVX instructions can read operands from either the L2 cache or VTCM, all vector scatter/gather operations and all HMX matrix instructions can only address VTCM. Furthermore, the compute throughput disparity between HVX and HMX is nearly three orders of magnitude: a single HVX thread achieves 32.93GFLOPs on FP16 GEMM, whereas the HMX unit delivers 12,032.54GFLOPs (12.03TFLOPs) on FP16 GEMM.Executing matrix multiplication on HMX requires strict adherence to hardware tile geometry. For FP16 operations, the fundamental HMX data unit is a 32×32 matrix tile occupying exactly 2,048bytes (2KiB). Both activation and weight tiles must reside in VTCM in a specialized hardware layout where every two adjacent rows are cross-lane permuted to match a transposed 2×32 sub-matrix structure, and weight tiles are arranged in column-major order to feed the tile-level inner-product array. Consequently, an optimal QNN/Hexagon execution graph uses HVX threads to perform on-the-fly cross-lane shuffling and element-wise normalizations (QNN_OP_LAYER_NORM, QNN_OP_ROTARY_EMBEDDING, QNN_OP_SOFTMAX) in VTCM while overlapping 2D DMA transfers with HMX tile accumulation (QNN_OP_MAT_MUL, QNN_OP_MULTI_HEAD_ATTENTION). Even with HMX acceleration, empirical profiling of Hexagon FlashAttention demonstrates that $84.6\%$ of total kernel latency is consumed by QKVO tensor load/store operations between DDR and VTCM, proving that reducing KV-cache byte volume via QuoKA, KeyDiff, and W4FP16a block quantization directly governs wall-clock speed.Platform Constraints: The 4 GiB DSP Virtual Address Cap, FastRPC, and OS Bandwidth ContentionDeploying production LLMs and multimodal pipelines onto Snapdragon silicon requires navigating three systems-level bottlenecks identified in recent platform engineering studies. The first bottleneck is the 32-bit (4GiB) DSP virtual address space limit: as documented in the Hexagon V79 Programmer's Reference Manual, user-mode processes on the Hexagon cDSP operate within a hard-capped 32-bit byte-addressable linear virtual address space (≤4GiB). A model exceeding 4GiB cannot be memory-mapped into the DSP simultaneously. In ggml-hexagon, models exceeding this boundary, such as 9B parameter checkpoints, suffer a $-14.3\%$ throughput penalty due to mandatory mirror-memcpy fallbacks from CPU-allocated heap buffers. Within the official Qualcomm AI Engine Direct (QNN / QAIRT) and Genie SDK stack, this hardware cap is resolved via ahead-of-time graph partitioning (qnn-context-binary-generator), which compiles models into W4A16 (W4FP16a) quantized context binary shards—such as 4 shards for Qwen3-4B on Snapdragon 8 Elite V79/V81, or 8 shards totaling 5.7GB for Llama-3-8B on the 100-TOPS Dragonwing IQ-9075 EVK—that fit cleanly within HTP buffer and virtual address limits.The second systems constraint involves FastRPC versus DSPQueue transport overhead across the processor interconnect. Communication between the ARM Application Processor (Oryon/Kryo CPU) and the Hexagon cDSP traverses the FastRPC kernel driver and ION shared memory buffers. Replacing legacy dspqueue serialization with a unified FastRPC ION mempool architecture (GGML_HEXAGON_USE_MEMPOOL=ON) eliminates per-buffer ION registration overhead and yields $43.8\%$ to $80.5\%$ token generation speedups on Snapdragon 8 Elite across 1B–4B parameter models. Similarly, consolidating split encoder/decoder pipelines into monolithic serialized context binaries with 64 KB L1 double-buffered RPCMEM copies (49.2GB/s, 2.2ms bus time) and 1.7ms FastRPC transport achieves a $98.7\%$ NPU pipeline duty cycle on Snapdragon 8 Elite.The third systems constraint stems from operating system scheduler blindness and memory bus contention. On Snapdragon 8 Elite, the CPU cluster enforces memory Quality-of-Service (QoS) via ARM Memory System Resource Partitioning and Monitoring (MPAM) and memlat governors. However, kernel device-tree configurations originally designed for <16ms ISP camera deadlines grant the NPU privileged direct memory paths and explicitly exempt NPU traffic from thermal throttling and CPU stall monitors. Because QNN executes compiled graphs as monolithic units whose smallest runnable chunk for an 8B model takes 5--8ms—exceeding the ∼1.125ms theoretical bandwidth regulation window—unregulated NPU inference saturates LPDDR5X bandwidth and induces UI frame jank. 0606             sim_to_anchor = (k_norm * anchor_mu).sum(dim=-1).mean(dim=1)  # [B, M]
0607             # Retain tokens maximizing (-sim_to_anchor)
0608             _, top_rel = torch.topk(-sim_to_anchor[0], k=middle_budget, sorted=False)

0611         elif self.policy == "quoka":

0613             # 1. Subselect informative queries furthest from mean query M_Q (if Q_len > 1)

0625             salience = qk_rel * v_norm
0626             _, top_rel = torch.topk(salience[0], k=middle_budget, sorted=False)

0931     def _sample(logits: torch.Tensor, temperature: float = 0.0, top_p: float = 1.0) -> torch.Tensor:
0932         if temperature <= 1e-5:
0933             return torch.argmax(logits, dim=-1)
0934         scaled = logits / temperature
0935         if top_p < 1.0:
0936             sorted_logits, sorted_indices = torch.sort(scaled, descending=True)
0937             cum_probs = torch.cumsum(torch.softmax(sorted_logits, dim=-1), dim=-1)
0938             remove_mask = cum_probs > top_p
0939             remove_mask[..., 1:] = remove_mask[..., :-1].clone()
0940             remove_mask[..., 0] = 0
0941             indices_to_remove = remove_mask.scatter(1, sorted_indices, remove_mask)
0942             scaled = scaled.masked_fill(indices_to_remove, float("-inf"))
0943         probs = torch.softmax(scaled, dim=-1)
0944         return torch.multinomial(probs, num_samples=1).squeeze(-1)

1411 class _BM25Index:
1412     def __init__(self, item_ids: List[str], texts: List[str]) -> None:
1413         self.item_ids = item_ids
1414         self.term_counts = [Counter(tokenize(text)) for text in texts]
1415         self.doc_lengths = [sum(counts.values()) for counts in self.term_counts]
1416         self.average_length = (
1417             sum(self.doc_lengths) / len(self.doc_lengths) if self.doc_lengths else 0.0
1418         )
1419         self.document_frequency: Dict[str, int] = {}
1420         for counts in self.term_counts:
1421             for term in counts:
1422                 self.document_frequency[term] = self.document_frequency.get(term, 0) + 1
1423 
1424     def search(self, query: str, k: int) -> List[Tuple[str, float]]:
1425         terms = tokenize(query)
1426         if not terms or not self.item_ids or self.average_length <= 0:
1427             return []
1428         k1, b = 1.2, 0.75
1429         n_docs = len(self.item_ids)
1430         scored: List[Tuple[str, float]] = []
1431         for item_id, counts, length in zip(self.item_ids, self.term_counts, self.doc_lengths):
1432             score = 0.0
1433             for term in terms:
1434                 frequency = counts.get(term, 0)
1435                 if frequency == 0:
1436                     continue
1437                 df = self.document_frequency.get(term, 0)
1438                 if df == 0:
1439                     continue
1440                 idf = math.log(1.0 + (n_docs - df + 0.5) / (df + 0.5))
1441                 denom = frequency + k1 * (1.0 - b + b * length / self.average_length)
1442                 score += idf * frequency * (k1 + 1.0) / denom
1443             if score > 0:
1444                 scored.append((item_id, score))
1445         scored.sort(key=lambda pair: (-pair[1], pair[0]))
1446         return scored[:k]

1449 class _DenseSubwordIndex:
1450     """Deterministic L2-normalized character-3gram & token projection index for zero-network
1451     semantic similarity, with automatic upgrade to sentence-transformers if installed.
1452     """
1453 
1454     def __init__(self, item_ids: List[str], texts: List[str], dim: int = 256) -> None:
1455         self.item_ids = item_ids
1456         self.dim = dim
1457         self.vectors = [self._embed(t) for t in texts]
1458 
1459     def _embed(self, text: str) -> List[float]:
1460         tokens = tokenize(text)
1461         if not tokens:
1462             return [0.0] * self.dim
1463         vec = [0.0] * self.dim
1464         for tok in tokens:
1465             padded = f"<{tok}>"
1466             for i in range(max(1, len(padded) - 2)):
1467                 trigram = padded[i : i + 3]
1468                 digest = hashlib.md5(trigram.encode("utf-8")).digest()
1469                 idx = int.from_bytes(digest[:2], "little") % self.dim
1470                 sign = 1.0 if (digest[2] & 1) == 0 else -1.0
1471                 vec[idx] += sign
1472         norm = math.sqrt(sum(v * v for v in vec))
1473         if norm > 1e-9:
1474             vec = [v / norm for v in vec]
1475         return vec
1476 
1477     def search(self, query: str, k: int) -> List[Tuple[str, float]]:
1478         q_tokens = set(tokenize(query))
1479         if not q_tokens:
1480             return []
1481         q_vec = self._embed(query)
1482         scored: List[Tuple[str, float]] = []
1483         for item_id, d_vec in zip(self.item_ids, self.vectors):
1484             cos_sim = sum(a * b for a, b in zip(q_vec, d_vec))
1485             if cos_sim > 0.15:
1486                 scored.append((item_id, cos_sim))
1487         scored.sort(key=lambda pair: (-pair[1], pair[0]))
1488         return scored[:k]

1549         """Execute Hybrid BM25 + Dense retrieval with Reciprocal Rank Fusion (RRF)."""
1550         if not query or not query.strip() or k <= 0:
1551             return []

1553             injected = getattr(self.engine, "retrieve", None)

1558             return []

1561         if q_terms and q_terms.issubset(_OUT_OF_SCOPE_TERMS):
1562             return []

1565         if not bm25_hits:
1566             return []

1578             if item_id in rrf_scores:
1579                 rrf_scores[item_id] += 0.5 / (rrf_k + rank)
1580                 comp_scores[item_id]["dense"] = round(float(d_score), 4)
1581 
1582         ranked = sorted(rrf_scores.items(), key=lambda pair: (-pair[1], pair[0]))[:k]

2245 In depthwise-separable convolutions and transformer projections, dynamic weight ranges vary wildly across channels. Applying a uniform tensor-wide quantization grid clips channels with large outliers while crushing small-range channels to zero, which causes MobileNetV2 ImageNet top-1 accuracy to collapse from $71.72\%$ in FP32 to $0.12\%$ under naive INT8 quantization. Exploiting the positive scaling equivariance of piecewise linear activations f(sx)=sf(x), Cross-Layer Equalization (CLE) rescales consecutive weight tensors W(1) and W(2) via a diagonal scaling matrix $S = \text{diag}(s_1, \dots, s_C)$ such that W(1)=S-1W(1) and W(2)=W(2)S, equalizing per-channel ranges. Alone, CLE restores MobileNetV2 INT8 accuracy to $69.91\%$; when combined with high-bias absorption and analytic or empirical Bias Correction in a Data-Free Quantization (DFQ) workflow, INT8 accuracy reaches $70.92\%$, surpassing per-channel quantization ($70.65\%$) while maintaining fast per-tensor HTP vector execution.
2246 To push quantization to ultra-low bitwidths (such as INT4 weights), the Amsterdam team proved that standard RTN minimizes the point-wise weight error $\|W - Q(W)\|_F^2$, which ignores how weight quantization errors correlate across input activations x. In Benchmark::run_single (src/benchmark/benchmark.cpp:51-89), the query tensor q is allocated with shape {n_heads, 1, head_dim} where n_heads = 32 and head_dim = 64 (32×1×64=2,048 floats), whereas k_tok and v_tok are stored into the cache with shape {n_kv_heads, 1, head_dim} where n_kv_heads = 8 (8×1×64=512 floats). Inside the token loop, the retrieval buffers k_ret and v_ret are initialized with shape {1, 1, head_dim} (64 floats). 2359 Mathematical Formulation of VTCM-Aware H2O-QUOKA and Pairwise KeyDiff Eviction
2360 To replace the broken mean-key proxy in QUOKAKVCache and the naive newest-key comparison in KeyDiffKVCache, the remediated architecture synthesizes Heavy-Hitter Oracle (H2O) cumulative attention tracking with Query-Oriented Knowledge Allocation (QUOKA) and Anchor-Free Pairwise KeyDiff redundancy elimination. Let the GQA Transformer have L layers, Hq query heads, Hkv key-value heads, group size G=Hq/Hkv, and head dimension dh. At layer $l \in \{0, \dots, L-1\}$, when S tokens are resident in the cache at original sequence positions $\mathcal{P}^{(l)} = (p_1, p_2, \dots, p_S)$, the contiguous resident key and value tensors have shape [Hkv,S,dh]. For a query tensor Q(l)∈RHq×Lq×dh at sequence positions $(q_1, \dots, q_{L_q})$, query head $h \in \{0, \dots, H_q - 1\}$ maps to KV head $h_{kv} = \lfloor h / G \rfloor$. The scaled dot-product attention logits and causal probabilities are given by:
2361 
2362 Ah,i,j(l)=Qh,i(l)⊤Khkv,j(l)dh+Mi,j,Ph,i,j(l)=expAh,i,j(l)m=1SexpAh,i,m(l)
2363 where Mi,j=0 if pj≤qi and -∞ otherwise. Crucially, rotary positional embeddings (RoPE) with model-specific base θRoPE∈{105,106} are applied using each token's true original position pj prior to caching, ensuring that evicting an interior token never corrupts the relative phase angle ϕ(pj,2m)=pj⋅θRoPE-2m/dh of subsequent tokens.
2364 During every prefill and decode step, the Query-Aware Heavy-Hitter QUOKA (H2O-QUOKA) algorithm aggregates the post-softmax attention probability mass received by each resident token $j \in \{1, \dots, S\}$ across all Hq query heads and query positions:
2365 
2366 sj(l)(t)=γsj(l)(t-1)+1HqLqh=0Hq-1i=1LqPh,i,j(l)
2367 where γ∈(0,1] (default γ=0.95) is an exponential decay factor balancing cumulative Heavy-Hitter importance (H2O) with immediate current-query relevance (QUOKA). To preserve local syntactic coherence and prevent attention-sink collapse, the cache partitions its per-layer capacity Clayer into three disjoint regions: an Attention Sink Guard (Ssink) pinning the first $N_{\text{sink}} = \min(4, \lfloor 0.05 \, C_{\text{layer}} \rfloor)$ initial prompt tokens where transformer layers route excess attention mass as no-op sinks; a Recent Locality Window (Srecent) protecting the most recent $N_{\text{recent}} = \max(1, \lfloor 0.20 \, C_{\text{layer}} \rfloor)$ tokens (always including the current token); and an Evictable Working Pool (Spool) spanning the interior tokens. When S>Clayer, H2O-QUOKA evicts the token j*∈Spool that minimizes the combined query-attention score and L2 value-norm contribution:
2368 $$j^*_{\text{QUOKA}} = \arg\min_{j \in \mathcal{S}_{\text{pool}}} \left( s_j^{(l)}(t) \cdot \left\| V_{:, j, :}^{(l)} \right\|_2 \right)$$
2369 Weighting the attention score sj(l)(t) by the value vector norm $\|V_{:, j, :}^{(l)}\|_2$ directly minimizes the upper bound on the attention output perturbation $\left\| P_{:, :, j}^{(l)} V_{:, :, j}^{(l)} \right\|_2$ induced by evicting token j. Complementing H2O-QUOKA, the remediated Anchor-Free Redundancy KeyDiff policy replaces the naive newest-key comparison (entries.back()) by maintaining the running normalized key centroid $\mu_K^{(l)} = \frac{1}{S}\sum_{j=1}^S \frac{K_j^{(l)}}{\|K_j^{(l)}\|_2}$ and computing each evictable token's maximum cosine similarity to its temporal neighbors and the centroid:
2370 $$r_j^{(l)} = \frac{1}{2} \cos\left(K_j^{(l)}, \mu_K^{(l)}\right) + \frac{1}{2} \max_{m \in \{j-1, j+1\} \cap \{1 \dots S\}} \cos\left(K_j^{(l)}, K_m^{(l)}\right), \quad j^*_{\text{KeyDiff}} = \arg\max_{j \in \mathcal{S}_{\text{pool}}} r_j^{(l)}$$
2371 Evicting the token with the highest similarity score rj(l) removes the most geometrically redundant key vector in the subspace while preserving orthogonal, high-information keys in O(S⋅dh) time. When combined with AIMET Cross-Layer Equalization and AdaRound quantization, these cache budgets compress a 2,048-token context window from 45.0MB (SmolLM2-135M FP16) and 24.0MB (Qwen2.5-0.5B FP16) directly into the 4MB to 8MB Hexagon VTCM SRAM envelope.

2583 Tensor CPUBackend::dot_product_attention(const Tensor& q, const Tensor& k,
2584                                          const Tensor& v, const Tensor* mask) {
2585   if (q.shape().size() != 3 || k.shape().size() != 3 || v.shape().size() != 3) {
2586     throw std::invalid_argument("dot_product_attention requires 3D tensors [heads, seq, dim]");
2587   }
2588   size_t n_heads = q.shape()[0];
2589   size_t q_len = q.shape()[1];
2590   size_t head_dim = q.shape()[2];
2591 
2592   size_t n_kv_heads = k.shape()[0];
2593   size_t kv_len = k.shape()[1];
2594   if (n_kv_heads == 0 || n_heads < n_kv_heads || (n_heads % n_kv_heads != 0)) {
2595     throw std::invalid_argument("Invalid GQA head ratio: n_heads must be a multiple of n_kv_heads");
2596   }
2597   if (v.shape()[0] != n_kv_heads || v.shape()[1] != kv_len ||
2598       k.shape()[2] != head_dim || v.shape()[2] != head_dim) {
2599     throw std::invalid_argument("K/V shape mismatch in dot_product_attention");
2600   }
2601 
2602   size_t group_size = n_heads / n_kv_heads;
2603   float scale = 1.0f / std::sqrt(static_cast<float>(head_dim));
2604 
2605   Tensor scores(DType::F32, {n_heads, q_len, kv_len});
2606   float* sd = scores.data_f32();
2607   const float* qd = q.data_f32();
2608   const float* kd = k.data_f32();
2609 
2610   // Compute scaled Q * K^T with proper GQA head group mapping: kv_h = h / group_size
2611   for (size_t h = 0; h < n_heads; ++h) {
2612     size_t kv_h = h / group_size;
2613     for (size_t qi = 0; qi < q_len; ++qi) {
2614       const float* q_row = qd + (h * q_len + qi) * head_dim;
2615       float* s_row = sd + (h * q_len + qi) * kv_len;
2616       for (size_t ki = 0; ki < kv_len; ++ki) {
2617         const float* k_row = kd + (kv_h * kv_len + ki) * head_dim;
2618         float sum = 0.0f;
2619         for (size_t d = 0; d < head_dim; ++d) {
2620           sum += q_row[d] * k_row[d];
2621         }
2622         s_row[ki] = sum * scale;
2623       }
2624     }
2625   }
2626 
2627   if (mask) {
2628     const float* md = mask->data_f32();
2629     size_t mask_elems = mask->numel();
2630     size_t slice_elems = q_len * kv_len;
2631     for (size_t h = 0; h < n_heads; ++h) {
2632       float* s_head = sd + h * slice_elems;
2633       const float* m_head = (mask_elems == n_heads * slice_elems) ? (md + h * slice_elems) : md;
2634       for (size_t i = 0; i < slice_elems; ++i) {
2635         s_head[i] += m_head[i];
2636       }
2637     }
2638   }
2639 
2640   softmax_inplace(scores);
2641 
2642   // Per-head batched multiplication: out[h] = scores[h] ([q_len, kv_len]) * v[kv_h] ([kv_len, head_dim])
2643   Tensor out(DType::F32, {n_heads, q_len, head_dim});
2644   const float* vd = v.data_f32();
2645   float* od = out.data_f32();
2646 
2647   for (size_t h = 0; h < n_heads; ++h) {
2648     size_t kv_h = h / group_size;
2649     const float* s_head = sd + h * q_len * kv_len;
2650     const float* v_head = vd + kv_h * kv_len * head_dim;
2651     float* o_head = od + h * q_len * head_dim;
2652 
2653     sgemm_f32(false, false,
2654               static_cast<int>(q_len), static_cast<int>(head_dim), static_cast<int>(kv_len),
2655               1.0f, s_head, static_cast<int>(kv_len),
2656               v_head, static_cast<int>(head_dim),
2657               0.0f, o_head, static_cast<int>(head_dim));
2658   }
2659 
2660   return out;
2661 }

2683 // -- KeyDiff: Anchor-free centroid + temporal neighbor redundancy eviction --
2684 uint32_t KeyDiffKVCache::select_eviction_candidate(uint32_t layer) {
2685   auto& entries = caches_[layer].entries;
2686   size_t n = entries.size();
2687   if (n <= 2) return 0;
2688 
2689   // Protect attention sink (index 0) and newest token (index n - 1)
2690   size_t key_len = entries[0].key.numel();
2691   std::vector<float> centroid(key_len, 0.0f);
2692   for (const auto& e : entries) {
2693     const float* kd = e.key.data_f32();
2694     for (size_t d = 0; d < key_len; ++d) centroid[d] += kd[d];
2695   }
2696   for (size_t d = 0; d < key_len; ++d) centroid[d] /= static_cast<float>(n);
2697 
2698   uint32_t victim = 1;
2699   float max_redundancy = -std::numeric_limits<float>::infinity();
2700 
2701   for (uint32_t i = 1; i < n - 1; ++i) {
2702     const float* ki = entries[i].key.data_f32();
2703     float sim_centroid = cosine_similarity(ki, centroid.data(), key_len);
2704     float sim_prev = cosine_similarity(ki, entries[i - 1].key.data_f32(), key_len);
2705     float sim_next = cosine_similarity(ki, entries[i + 1].key.data_f32(), key_len);
2706     float neighbor_sim = std::max(sim_prev, sim_next);
2707     float redundancy = 0.5f * sim_centroid + 0.5f * neighbor_sim;
2708 
2709     if (redundancy > max_redundancy) {
2710       max_redundancy = redundancy;
2711       victim = i;
2712     }
2713   }
2714   return victim;

2717 // -- QUOKA (H2O-QUOKA): Query-oriented attention relevance * Value L2-norm with Sink/Recency guard --
2718 uint32_t QUOKAKVCache::select_eviction_candidate(uint32_t layer) {
2719   auto& entries = caches_[layer].entries;
2720   size_t n = entries.size();
2721   if (n <= 2) return 0;
2722 
2723   // Protect initial attention sink (index 0) and most recent 20% window (at least newest token)
2724   size_t recent_guard = std::max<size_t>(1, n / 5);
2725   size_t pool_end = (n > recent_guard) ? (n - recent_guard) : (n - 1);
2726   if (pool_end <= 1) return 1;
2727 
2728   // Use the latest query proxy (newest key-query direction + accumulated access score)
2729   const float* query_proxy = entries.back().key.data_f32();
2730   size_t key_len = entries.back().key.numel();
2731   float scale = 1.0f / std::sqrt(static_cast<float>(key_len));
2732 
2733   uint32_t victim = 1;
2734   float min_utility = std::numeric_limits<float>::infinity();
2735 
2736   for (uint32_t i = 1; i < pool_end; ++i) {
2737     const float* ki = entries[i].key.data_f32();
2738     const float* vi = entries[i].value.data_f32();
2739     size_t val_len = entries[i].value.numel();
2740 
2741     float dot = 0.0f;
2742     for (size_t d = 0; d < key_len; ++d) dot += query_proxy[d] * ki[d];
2743     float attn_logit = std::exp(dot * scale);
2744 
2745     float v_norm_sq = 0.0f;
2746     for (size_t d = 0; d < val_len; ++d) v_norm_sq += vi[d] * vi[d];
2747     float v_norm = std::sqrt(v_norm_sq);
2748 
2749     // Combine accumulated H2O heavy-hitter score with immediate query-value impact
2750     float utility = entries[i].last_access_score * attn_logit * (1.0f + v_norm);
2751     if (utility < min_utility) {
2752       min_utility = utility;
2753       victim = i;
2754     }
2755   }
2756   return victim;
2757 }

3280 def apply_aimet_style_cle_and_adaround(
3281     weight: torch.Tensor,
3282     calib_input: torch.Tensor,
3283     n_bits: int = 4,
3284     iters: int = 200,
3285 ) -> Tuple[torch.Tensor, torch.Tensor]:
3286     """AIMET-inspired Adaptive Rounding (AdaRound) minimizing ||W x - W_quant x||_F^2.
3287 
3288     Instead of naive Round-to-Nearest (RTN), optimizes a continuous rounding offset V
3289     using a rectified sigmoid h(V) so quantized weights preserve layer output activations.
3290     """
3291     with torch.no_grad():
3292         qmax = float((1 << (n_bits - 1)) - 1)
3293         qmin = -float(1 << (n_bits - 1))
3294         scale = weight.abs().amax(dim=1, keepdim=True).clamp(min=1e-8) / qmax
3295         w_scaled = weight / scale
3296         w_floor = torch.floor(w_scaled)
3297         rest = w_scaled - w_floor  # in [0, 1)
3298 
3299     # Continuous parameter V initialized so rectified sigmoid h(V) == rest
3300     gamma, zeta = -0.1, 1.1
3301     init_p = ((rest - gamma) / (zeta - gamma)).clamp(1e-4, 1.0 - 1e-4)
3302     V = nn.Parameter(torch.log(init_p / (1.0 - init_p)))
3303     optimizer = torch.optim.Adam([V], lr=0.05)
3304 
3305     x = calib_input.detach().float()
3306     orig_out = torch.matmul(x, weight.detach().float().T)
3307 
3308     for step in range(iters):
3309         optimizer.zero_grad()
3310         h_v = torch.clamp(torch.sigmoid(V) * (zeta - gamma) + gamma, 0.0, 1.0)
3311         w_soft = torch.clamp(w_floor + h_v, qmin, qmax) * scale
3312         quant_out = torch.matmul(x, w_soft.T)
3313         recon_loss = torch.mean((orig_out - quant_out) ** 2)
3314         beta = max(2.0, 20.0 - 18.0 * (step / max(1, iters)))
3315         reg_loss = 0.01 * torch.mean(1.0 - torch.abs(2.0 * h_v - 1.0) ** beta)
3316         loss = recon_loss + reg_loss
3317         loss.backward()
3318         optimizer.step()
3319 
3320     with torch.no_grad():
3321         h_final = (torch.sigmoid(V) * (zeta - gamma) + gamma >= 0.5).float()
3322         w_quant_int = torch.clamp(w_floor + h_final, qmin, qmax)
3323         w_dequant = w_quant_int * scale
3324     return w_dequant, scale
